# هدهد — بستهٔ فرانت‌اند + بک‌اند متصل

## اجرای محلی

### ۱) بک‌اند و پایگاه داده
از پوشهٔ `buildx_backend`:

```bash
cp .env.example .env
```
سپس در فایل `.env` مقدار `SECRET_KEY` را با یک مقدار تصادفی طولانی و `LLM_API_KEY` را با کلید سرویس‌دهندهٔ مدل زبانی خودتان جایگزین کنید. کلید LLM را هرگز در فرانت‌اند قرار ندهید.

```bash
docker compose up --build
```
API روی `http://localhost:8000` و مستندات آن روی `http://localhost:8000/docs` در دسترس خواهد بود.

### ۲) فرانت‌اند
در ترمینال دیگری:

```bash
cd hodhod-frontend
cp .env.example .env.local
npm install
npm run dev
```
سپس `http://localhost:3000` را باز کنید. آدرس API از `NEXT_PUBLIC_API_URL` خوانده می‌شود.

## جریان‌هایی که متصل شده‌اند
- ثبت‌نام و ورود، JWT و دریافت هویت کاربر
- محافظت صفحات داشبورد و خروج از حساب
- مصاحبهٔ واقعی با ایجنت و ارسال پاسخ‌ها به بک‌اند
- تولید رزومه از اطلاعات مصاحبه و نمایش آخرین رزومهٔ ذخیره‌شده
- جست‌وجوی آگهی‌ها از دیتابیس بک‌اند و تحلیل تناسب با ایجنت

## محدودیت‌ها و قبل از دمو
- این بسته در این محیط روی سرور شما deploy نشده است؛ اجرای محلی به معنی انتشار آنلاین نیست.
- برای تولید رزومه و تحلیل تطبیق، کلید LLM معتبر و دسترسی شبکه از بک‌اند لازم است.
- فهرست آگهی‌ها خودکار از سایت‌های استخدامی جمع‌آوری نمی‌شود؛ باید آگهی‌ها از منبع مجاز به API/دیتابیس اضافه شوند.
- پس از تغییر دامنهٔ فرانت‌اند، دامنه را به `CORS_ORIGINS` بک‌اند اضافه کنید. در محیط عمومی HTTPS و `SECRET_KEY` امن الزامی است.
- قبل از ارسال مسابقه، جریان ثبت‌نام تا ساخت رزومه و تحلیل آگهی را در محیطی با PostgreSQL و کلید واقعی LLM سرتاسری آزمایش کنید.
