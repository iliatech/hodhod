# راهنمای انتشار هدهد (Render + Vercel)

این پروژه از یک فرانت‌اند Next.js، یک API با FastAPI و PostgreSQL استفاده می‌کند. فایل `render.yaml` پیکربندی API و دیتابیس را برای Render آماده کرده و پوشه `hodhod-frontend` برای Vercel تنظیم شده است.

## آگهی‌های شغلی

- دکمه «به‌روزرسانی آگهی‌های زنده» از دو منبع عمومی استفاده می‌کند: [Arbeitnow](https://www.arbeitnow.com/) و [Remote OK](https://remoteok.com/).
- آگهی‌ها از نظر مشاغل فناوری اطلاعات فیلتر می‌شوند و لینک آگهی اصلی و نام منبع نگه داشته می‌شود.
- توضیح اصلی آگهی حفظ می‌شود؛ دکمه «ترجمه فارسی» با مدل زبانی ترجمهٔ فارسی را هنگام درخواست تولید می‌کند.
- برای تحلیل تناسب و ترجمه باید `LLM_API_KEY` در تنظیمات سرور قرار گیرد. هر درخواست ترجمه/تحلیل می‌تواند هزینهٔ ارائه‌دهندهٔ مدل داشته باشد.
- فیدهای عمومی ممکن است آگهی‌های منقضی یا منطقه‌محدود داشته باشند؛ کاربر باید شرایط و اعتبار آگهی را در سایت اصلی بررسی کند. منابع باید در رابط باقی بمانند.

## ۱) آماده‌سازی GitHub

۱. ZIP را استخراج کن و کل محتویات را در یک مخزن خصوصی GitHub قرار بده.
۲. ساختار ریشه باید شامل `render.yaml`، `buildx_backend/` و `hodhod-frontend/` باشد.
۳. فایل‌های `.env` واقعی و کلیدهای API را commit نکن.

## ۲) انتشار بک‌اند و PostgreSQL در Render

۱. وارد Render شو و از داشبورد، ساخت Blueprint از مخزن GitHub را انتخاب کن.
۲. فایل `render.yaml` را تأیید کن. این تنظیم از پلن‌های پولی Render استفاده می‌کند؛ پیش از تأیید، هزینهٔ فعلی سرویس وب و دیتابیس را در داشبورد بررسی کن.
۳. برای `LLM_API_KEY` کلید ارائه‌دهندهٔ مدل را در Environment سرویس `hodhod-api` وارد کن. کلید را در فرانت‌اند یا GitHub قرار نده.
۴. پس از انتشار، آدرس API را بردار، مثلاً `https://hodhod-api.onrender.com`.
۵. بررسی کن `https://YOUR-API/health` پاسخ `{"status":"ok",...}` بدهد و `https://YOUR-API/docs` باز شود.

## ۳) انتشار فرانت‌اند در Vercel

۱. در Vercel یک پروژهٔ جدید از همان مخزن GitHub بساز.
۲. در Project Settings → Build and Deployment، **Root Directory** را روی `hodhod-frontend` بگذار و Next.js را به‌عنوان Framework حفظ کن.
۳. در Environment Variables مقدار زیر را اضافه کن:
   - `NEXT_PUBLIC_API_URL` = آدرس HTTPS بک‌اند Render، بدون اسلش پایانی.
۴. Deploy کن و آدرس دامنهٔ Vercel را بردار، مثلاً `https://hodhod.vercel.app`.

## ۴) اتصال CORS و انتشار مجدد

در Render → `hodhod-api` → Environment، مقدار `CORS_ORIGINS` را به دامنهٔ واقعی فرانت‌اند Vercel تنظیم کن (بدون `/` در انتها). اگر دامنهٔ Preview جداگانه استفاده می‌کنی، آن را هم به‌صورت جداشده با کاما اضافه کن. سپس API را redeploy/restart کن.

## ۵) تست نهایی

- `GET /health` بدون ورود باید کار کند.
- ثبت‌نام و ورود کاربر را در فرانت‌اند تست کن.
- در داشبورد آگهی‌ها روی «به‌روزرسانی آگهی‌های زنده» بزن.
- بازشدن لینک اصلی آگهی، ترجمهٔ فارسی و تحلیل تناسب را بررسی کن.
- پروفایل را با مهارت‌ها/تجربه‌های واقعی تکمیل کن؛ بعد تحلیل تناسب و ساخت رزومه را تست کن.
- ساخت رزومه و ترجمه نیازمند کلید LLM معتبر است. از اطلاعات ساختگی به‌عنوان تجربهٔ واقعی استفاده نکن.

## محدودیت مهم

من می‌توانم پیکربندی و کد را آماده کنم، اما انتشار واقعی نیازمند دسترسی به حساب GitHub/Render/Vercel و تأیید کاربر در همان سرویس‌هاست. این ZIP به‌خودی‌خود به معنی deploy شدن نیست. برای محیط تولیدی بلندمدت، به‌جای `create_all` در شروع برنامه، مهاجرت‌های دیتابیس مانند Alembic و مانیتورینگ مناسب اضافه شود.
